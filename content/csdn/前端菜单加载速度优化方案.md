## 前端菜单加载速度优化方案

### 1. 背景与目标

项目中的菜单页面普遍采用 Vue Router 动态路由 + 页面组件懒加载 + 页面挂载后请求首屏接口的模式。用户点击菜单后，通常会同时等待两类耗时：
页面组件 chunk 下载与解析。页面首屏接口响应。
当后端接口响应较慢，或者页面本身依赖大体积库时，用户会明显感到菜单“点进去很慢”。本方案用于降低菜单切换等待时间，核心目标是：
用户点击菜单前，尽量提前加载页面组件。对稳定 GET 接口做短时间内存缓存，减少重复请求等待。对高频慢页面做首屏数据预取，让用户进入页面时直接命中缓存。对大体积依赖做异步加载，避免阻塞页面主体显示。

### 2. 总体方案

本次采用四层优化：

显式 GET 短缓存
在 requestJson 层支持 cacheTtlMs。只有显式传入 cacheTtlMs 的 GET 请求才缓存。非 GET 写操作成功后自动清空缓存，避免创建、编辑、删除后继续读取旧数据。

页面组件预加载
菜单项 hover/focus 时，提前加载对应 Vue 页面组件 chunk。登录后浏览器空闲时，预加载前几个可访问菜单组件。对明确慢的页面强制优先预加载组件。

重点页面首屏数据预取
针对 算力观测、可视化监控告警、纳管信息展示，在用户 hover 菜单或浏览器空闲时预请求首屏数据。预请求结果进入 GET 短缓存，点击进入页面时直接复用。

大体积依赖异步加载
纳管信息展示 原先静态引入 echarts，页面 chunk 约 1MB。改为 import('echarts') 动态加载，使页面主体 chunk 降到约 9KB，图表库独立异步加载。

### 3. 适用场景

适合接入短缓存/预取的接口：
字典下拉、表单初始化数据。列表页首屏数据，且允许 10-60 秒内轻微延迟。监控类页面的概览数据，但 TTL 应较短。用户反复切换菜单会重复请求的 GET 接口。
不建议缓存或要谨慎缓存的接口：
日志实时流、任务详情实时状态。下载、上传、取消、删除、启停等写操作。轮询中强实时要求的状态接口，除非 TTL 很短且业务接受。

### 4. 关键实现一：GET 短缓存

实现位置：frontend/src/api/http.ts
关键思路：
扩展 RequestInit，增加 cacheTtlMs 和 cacheKey。缓存 key 由 token + url 组成，避免不同用户之间串数据。缓存中保存两种状态：
promise：请求还在进行中，后续相同请求复用同一个 Promise。value：请求完成后保存响应副本。
返回缓存数据时做深拷贝，避免页面修改响应对象污染缓存。非 GET 请求成功后执行 clearApiCache()。
核心代码：

```ts
export interface RequestJsonOptions extends RequestInit {
  cacheTtlMs?: number
  cacheKey?: string
}

interface ApiCacheEntry {
  expiresAt: number
  value?: ApiResponse
  promise?: Promise>
}

const apiCache = new Map()
const method = (options.method ?? 'GET').toUpperCase()
const url = joinUrl(baseUrl, path)
const shouldCache = method === 'GET' && (options.cacheTtlMs ?? 0) > 0
const cacheKey = shouldCache ? buildCacheKey(token, url, options) : ''

if (shouldCache) {
  const cached = apiCache.get(cacheKey)
  if (cached && cached.expiresAt > Date.now()) {
    if (cached.value) return cloneJson(cached.value) as ApiResponse
    if (cached.promise) return cloneJson(await cached.promise) as ApiResponse
  }
  apiCache.delete(cacheKey)
}
const payload = await requestPromise
if (method !== 'GET') clearApiCache()
return payload

```

接入方式：

```ts
const SHORT_CACHE_TTL_MS = 45_000

export async function getTrainCreateFormData() {
  const res = await requestJson(
    API_BASE_URL,
    '/api/model-train/create-form-data',
    { cacheTtlMs: SHORT_CACHE_TTL_MS },
  )
  return res.data
}

```

TTL 建议：
表单下拉、字段字典：45_000 ms。监控类概览/列表：15_000 ms。非实时配置类数据：可按业务放宽到 60_000 ms。

### 5. 关键实现二：页面组件预加载

实现位置：frontend/src/router/pageComponents.ts
项目原本使用 PAGE_COMPONENT_LOADERS 做动态路由组件懒加载。预加载直接复用这些 loader。
核心代码：

```ts
const preloadedPageIds = new Set()

export function preloadPageComponent(pageId: PageId): void {
  if (preloadedPageIds.has(pageId)) return
  const loader = PAGE_COMPONENT_LOADERS[pageId]
  if (typeof loader !== 'function') return
  preloadedPageIds.add(pageId)
  void Promise.resolve(loader()).catch(() => {
    preloadedPageIds.delete(pageId)
  })
}

```

空闲预加载：

```ts
export function preloadPageComponents(pageIds: PageId[], limit = 6): void {
  const run = () => {
    for (const pageId of pageIds.slice(0, limit)) preloadPageComponent(pageId)
  }
  if ('requestIdleCallback' in window) {
    window.requestIdleCallback(run, { timeout: 3000 })
    return
  }
  globalThis.setTimeout(run, 300)
}

```

### 6. 关键实现三：重点页面首屏数据预取

实现位置：frontend/src/services/pageDataPreload.ts
目标页面：
compute-observation：算力观测monitor-alert：可视化监控告警manage-info：纳管信息展示
设计要点：
只预取首屏默认参数。预取结果进入 requestJson 的 GET 短缓存。避免重复预取：使用 preloadedAt 和 inflight 控制。预取失败不打扰用户，只丢弃本次预取状态。
核心代码：

```ts
const preloadedAt = new Map()
const inflight = new Map>()
const PRELOAD_TTL_MS = 15_000

function shouldSkip(pageId: PageId): boolean {
  const last = preloadedAt.get(pageId) ?? 0
  return Date.now() - last < PRELOAD_TTL_MS
}

```

```ts
export function preloadPageData(pageId: PageId): void {
  if (shouldSkip(pageId) || inflight.has(pageId)) return
  const promise = runPreload(pageId)
  if (!promise) return
  inflight.set(pageId, promise)
  void promise
    .then(() => {
      preloadedAt.set(pageId, Date.now())
    })
    .catch(() => {
      preloadedAt.delete(pageId)
    })
    .finally(() => {
      inflight.delete(pageId)
    })
}

```

### 7. 关键实现四：大体积依赖异步加载

问题示例：纳管信息展示 页面静态引入 echarts 后，页面 chunk 约 1MB，首次点击必须等待图表库下载解析。
优化前：

```ts
import * as echarts from 'echarts'

```

优化后：

```ts
import type { ECharts } from 'echarts'

let echartsApi: typeof import('echarts') | null = null
let sourceChart: ECharts | null = null
let usageChart: ECharts | null = null

async function ensureEcharts() {
  if (!echartsApi) echartsApi = await import('echarts')
  return echartsApi
}

```

图表初始化：

```ts
async function initCharts(pieData: ManageInfoChartItem[], topUtil: ManageInfoTopUtilItem[]) {
  if (!sourceChartRef.value || !usageChartRef.value) return
  const echarts = await ensureEcharts()
  if (!sourceChartRef.value || !usageChartRef.value) return
  if (!sourceChart) sourceChart = echarts.init(sourceChartRef.value, 'dark')
  if (!usageChart) usageChart = echarts.init(usageChartRef.value, 'dark')
  applyChartOptions(pieData, topUtil)
}

```

接口返回后异步初始化图表，不阻塞页面主体渲染：

```ts
void initCharts(
  data.charts?.cardTypeDistribution ?? [],
  data.charts?.topUtilization ?? [],
)

```

优化效果：
ManageInfo 页面主 chunk 从约 1MB 降到约 9KB。echarts 被拆到单独异步 chunk。页面主体先显示，图表后加载。

### 8. 新页面复用接入步骤

#### 8.1 接入 GET 短缓存

判断接口是否适合缓存。在对应 API 文件定义 TTL。给 requestJson 第三个参数增加 cacheTtlMs。
示例：

```ts
const PAGE_CACHE_TTL_MS = 15_000

export async function getXxxOverview(pageNum: number, pageSize: number) {
  const qs = new URLSearchParams({ pageNum: String(pageNum), pageSize: String(pageSize) })
  const res = await requestJson(
    API_BASE_URL,
    `/api/xxx/overview?${qs}`,
    { cacheTtlMs: PAGE_CACHE_TTL_MS },
  )
  return res.data
}

```

#### 8.2 接入组件预加载

如果页面已经在 PAGE_COMPONENT_LOADERS 中注册，一般无需额外处理。菜单 hover/focus 会自动调用：

```ts

```

如果是特别慢的页面，可加入 AppLayout.vue 的优先预加载列表：

```ts
;(['compute-observation', 'monitor-alert', 'manage-info'] as PageId[]).forEach(preloadPageComponent)

```

#### 8.3 接入首屏数据预取

在 pageDataPreload.ts 增加页面预取函数。在 runPreload(pageId) 中注册页面。如果需要登录后空闲预取，则加入 preloadPriorityPageData()。
示例：

```ts
async function preloadXxxPage() {
  const { getXxxOverview } = await import('@/api/xxx')
  await getXxxOverview(1, DEFAULT_LIST_PAGE_SIZE)
}

function runPreload(pageId: PageId): Promise | null {
  if (pageId === 'xxx-page') return preloadXxxPage()
  return null
}

```

#### 8.4 拆分大依赖

如果构建结果显示某个页面 chunk 特别大，优先检查：
是否静态引入 echarts、monaco-editor、地图 SDK、富文本编辑器等大库。是否可改为动态 import()。是否可以让页面主体先渲染，大库稍后加载。

### 10. 注意事项

缓存必须显式启用
不要默认缓存所有 GET。状态变化快的接口要设置短 TTL 或不缓存。

写操作必须失效
当前 requestJson 已在非 GET 成功后自动 clearApiCache()。如果后续出现不走 requestJson 的写操作，需要手动清缓存。

不要在预取失败时提示用户
预取只是体验优化，失败不应打扰正常流程。正式进入页面时仍按页面自身错误处理展示提示。

预取范围要克制
不要登录后预取所有页面所有接口，避免给后端造成额外压力。优先预取明确慢、用户高频访问、首屏参数固定的页面。

监控类页面 TTL 不宜过长
建议 10-15 秒。页面自身轮询或手动刷新仍会按 TTL 判断是否重新请求。

大依赖优先动态加载
如果某个页面 chunk 超过几百 KB，先检查静态大依赖。页面主体和图表/编辑器/地图等重组件可以分阶段加载。

}

export function preloadPageData(pageId: PageId): void {
  if (shouldSkip(pageId) || inflight.has(pageId)) return
  const promise = runPreload(pageId)
  if (!promise) return
  inflight.set(pageId, promise)
  void promise
    .then(() => {
      preloadedAt.set(pageId, Date.now())
    })
    .catch(() => {
      preloadedAt.delete(pageId)
    })
    .finally(() => {
      inflight.delete(pageId)
    })
}

### 10. 注意事项

缓存必须显式启用
不要默认缓存所有 GET。状态变化快的接口要设置短 TTL 或不缓存。

写操作必须失效
当前 requestJson 已在非 GET 成功后自动 clearApiCache()。如果后续出现不走 requestJson 的写操作，需要手动清缓存。

不要在预取失败时提示用户
预取只是体验优化，失败不应打扰正常流程。正式进入页面时仍按页面自身错误处理展示提示。

预取范围要克制
不要登录后预取所有页面所有接口，避免给后端造成额外压力。优先预取明确慢、用户高频访问、首屏参数固定的页面。

监控类页面 TTL 不宜过长
建议 10-15 秒。页面自身轮询或手动刷新仍会按 TTL 判断是否重新请求。

大依赖优先动态加载
如果某个页面 chunk 超过几百 KB，先检查静态大依赖。页面主体和图表/编辑器/地图等重组件可以分阶段加载。
